# Maintainable Code Craft

一个领域中性的工程 Skill，用于让软件修改保持清晰、可验证、易维护。

它强调明确的责任归属、直接的设计、清晰的契约、与风险相称的验证，以及能够完整解决当前问题的最小实现。

## 适用范围

在编写、修改、重构、审查或生成代码时，可以把这个 Skill 作为通用的可维护性基线。具体项目的架构、业务规则、安全策略和运行流程仍由项目自身负责。

核心工作流保持简单：

`理解 -> 决策 -> 设计 -> 实现 -> 观察 -> 精炼 -> 验证 -> 清理`

对于很小的修改，这些步骤可以自然合并；对于较大的修改，只在风险和范围确实需要时增加深度。

## 核心原则

- 从真实调用方和当前实际行为出发理解代码。
- 每条规则或转换尽量只有一个清晰的责任归属。
- 只有在确实减少维护负担时才增加抽象。
- 优先直接、自然的实现，避免为假设中的未来提前堆叠层次。
- 只有当职责确实独立变化时才拆分边界。
- 在真正的信任边界进行校验，而不是层层重复检查。
- 让副作用和失败状态清晰可见。
- 注释解释不明显的原因和约束，而不是翻译语法。
- 在真实调用方最终使用的边界观察结果。
- 用能够证伪当前修改的定向验证支撑完成结论。
- 保留无关改动，并清理本次任务产生的临时残留。
- 项目特有的规则留在项目内部，不写进全局通用 Skill。

## 安装

把本仓库复制或克隆到你的编码助手所使用的 Skill 目录中，并保持 `SKILL.md` 位于该 Skill 文件夹根目录。不同宿主应用的具体 Skill 路径可能不同。

安装后，确认宿主能够发现名为 `maintainable-code-craft` 的 Skill。

## 使用方式

这个 Skill 既可以作为隐式工程基线，也可以显式调用。例如：

```text
使用 maintainable-code-craft 重构这个模块。
```

```text
检查这段实现是否存在不必要的复杂度或责任归属不清。
```

```text
用最小但完整的设计实现这个修改，并做定向验证。
```

当项目本地规则更具体时，以项目规则为准。

## 边界

这个公开 Skill 有意保持通用，不绑定特定框架、操作系统、部署方式、业务领域、数据来源或发布流程。

这种分离是有意的：可复用的工程原则放在这里；具体项目的知识留在拥有它的项目中。
